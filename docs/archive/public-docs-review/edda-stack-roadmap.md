# Roadmap

Current status and planned development.

## What Exists Today

### Kindling 1.0

**Status: Available**

Full observation capture and retrieval:

- CLI for capture, search, export
- Capsule-based organisation
- SQLite storage
- Adapter framework
- MCP integration hooks

[Start using Kindling →](/docs/kindling/overview)

### Anvil 1.0

**Status: Available**

Full development validation:

- Architecture boundary checking
- Anti-pattern detection
- Watch mode
- GitHub integration
- VS Code extension

[Start using Anvil →](/docs/anvil/overview)

### APS 1.0

**Status: Available**

Full plan specification:

- Document format
- Validation tooling
- CLI support

[Start using APS →](/docs/aps/overview)

## What's Coming

### Ember (Candidate Layer)

**Status: In Design**

Planned capabilities:

- Manual promotion from Kindling
- Review workflow
- Team sharing
- Deduplication

### Edda (Curated Layer)

**Status: Planning**

Planned capabilities:

- Verified knowledge entries
- Search and discovery
- Versioning
- Context surfacing

### Enhanced Integrations

**Status: Ongoing**

Planned:

- Additional IDE integrations
- More adapter support
- Deeper MCP integration
- Workflow automation

## Timeline Philosophy

We don't provide specific dates because:

1. **Quality over schedule** — We ship when it's ready
2. **User-driven** — Priorities shift based on feedback
3. **Honesty** — Software estimation is notoriously unreliable

What we can say:

- Kindling, Anvil, and APS are production-ready today
- Ember is the next major addition
- We're actively developing

## How to Influence the Roadmap

### Feedback

Tell us what you need:

- [GitHub Issues](https://github.com/eddacraft/anvil-001/issues)
- Feature requests
- Bug reports

### Contribution

Contribute to development:

- Code contributions
- Documentation improvements
- Adapter development

### Adoption

Using the tools informs our priorities. The more feedback we get, the better we
can prioritise.

## Commitment

What we commit to:

1. **Stability** — Production-ready means stable
2. **Migration** — Clear upgrade paths between versions
3. **Communication** — Transparent about what's coming
4. **Support** — Responsive to issues and questions
