# HTML vs Markdown plan-loading token cost

Experiment to compare how many tokens Claude spends loading and processing the
same APS plan in three formats:

- `source.md` — frozen snapshot of `plans/modules/tui-dashboard-render.aps.md`
  (404 lines, representative module plan)
- `source.minimal.html` — semantic HTML, no classes or attributes
- `source.structured.html` — semantic HTML with `data-aps-*` attributes on
  work-item headings and task checkboxes

Both HTML files are generated by `convert.mjs` (zero-dep, deterministic). They
are committed so the bench compares fixed artifacts, not a live conversion.

## Regenerate HTML

```bash
node experiments/html-vs-markdown-tokens/convert.mjs
```

## Run the bench

Needs `ANTHROPIC_API_KEY` exported. Defaults to `claude-sonnet-4-6`, one run.

```bash
ANTHROPIC_API_KEY=sk-ant-... \
  node experiments/html-vs-markdown-tokens/bench.mjs

# Average across runs, pick a different model:
ANTHROPIC_API_KEY=sk-ant-... \
  node experiments/html-vs-markdown-tokens/bench.mjs --runs 3 --model claude-haiku-4-5-20251001
```

Reports per variant:

- `bytes` — file size on disk
- `count_tokens` — raw input token count from `POST /v1/messages/count_tokens`
- `prompt_in` / `prompt_out` — usage from a real `/v1/messages` round-trip with
  a fixed extraction task ("return every work item as JSON")
- `latency_ms` — round-trip latency
- `tokens_vs_md` — % difference from the markdown baseline

## Why this task

The processing prompt asks the model to walk every work item and return a strict
JSON shape with `id`, `priority`, `confidence`, and a `dependencyCount`. This
forces real structural reading rather than just summarisation, and keeps the
output size roughly constant across variants so the input-token comparison stays
clean.

## Caveats

- One model run is noisy; use `--runs 3+` for anything load-bearing.
- The structured HTML adds `data-aps-id` only to headings that already match
  `^[A-Z]+-\d+:`; it is a thin enrichment, not a full APS schema.
- The hand-rolled markdown → HTML converter handles the APS subset only
  (headers, GFM tables, blockquotes, bullets with one nesting level, task
  checkboxes, inline code/bold/italic/links, horizontal rules). It is not a
  general-purpose CommonMark renderer.
