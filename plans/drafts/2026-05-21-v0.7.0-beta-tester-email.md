## Body

> `$ anvil :: release notice`
>
> `[ OK ] v0.7.0-beta — Daemon-Working End-to-End Protection`

A new Anvil release is live. This is the one we've been building toward all
month — every protection layer now operates as a single verifiable claim, from
file-save through commit, push, and wrapped agent launch.

### What's new

- **End-to-end daemon-backed protection.** Hooks, the witness chain, baseline
  adoption, L4 policy, and `anvil-run` (the new wrapped-launch ingress for
  Claude Code / Codex / Aider / Cursor / Windsurf) operate as one pipeline.
  Every commit is witnessed; every save passes the same checks; every
  agent-driven write is attributable.
- **One typed protection claim across every surface.** `anvil status`,
  `anvil doctor`, the MCP server, and the TypeScript driver-client all emit
  the same shape — editors, CI, and agents read identical state.
- **Wrapped agent launch via `anvil-run`.** `anvil-run --tool claude-code -- <command>`
  wraps the agent process so the daemon can attribute work, enforce fences,
  and clean up stale sessions.
- **Signed `anvil update`.** Every supported install path now verifies a
  minisign signature on the downloaded binary before replacing the running one.
- **Hook coexistence with lefthook, husky, and pre-commit-framework.** No
  more `.git/hooks/` overwrites; Anvil registers as a managed entry under the
  host hook manager.
- **`anvil insights` weekly summary** — a periodic value signal during the
  quiet middle of normal use.

Full release notes:
https://github.com/eddacraft/anvil/releases/tag/v0.7.0-beta


### One thing to know about first invocation

If your refresh session has been idle, your first `anvil status` or
`anvil start` after upgrade will surface `state: "authRequired"`. Recovery
is one command:

```
anvil auth login
```

Then re-run whatever you were doing. This is deliberate — the v0.7.0-beta
auth surface distinguishes "needs login" from "login failed" so editors and
scripts can route you to the right step. Full migration note:
https://github.com/eddacraft/anvil/blob/main/docs/runbooks/v0.6.x-to-v0.7.0-beta-migration.md

### Known gaps we're transparent about

- The daemon's `session.report_process` IPC handler is not yet implemented.
  `anvil-run` recovers gracefully and exits cleanly, but you'll see a
  one-line stderr warning until the handler ships. Tracked in
  [#1827](https://github.com/eddacraft/anvil-001/issues/1827).
- The Marketplace publishing track (`anvil-action` GitHub Action) is still
  blocked on the licensing/pricing model lock. Not in this release.

A full Known Gaps list lives in the CHANGELOG.

### A specific ask: the Boring Week

This release is the one we want to **sit on** for a while. The release plan
calls for three or more of you to run v0.7.0-beta on real work for one
calendar week, under fresh-user config (no developer overrides). Any
disabled check, unresolved suppression, or hook bypass you hit blocks the
next release, so we'd rather hear about it now than later.

If you're up for it, just reply to this email with "I'm in" and roughly which
project you'll run it against. We'll send a one-page note covering what to
log and where to file feedback.

### How to report friction

- **Bugs / unexpected behaviour:** `anvil doctor --json` and paste the output

  https://github.com/eddacraft/anvil-001/issues.
- **Feature requests / "this would be nice":** reply to this email — Josh

- **Security issues:** see SECURITY.md for the disclosure path.
