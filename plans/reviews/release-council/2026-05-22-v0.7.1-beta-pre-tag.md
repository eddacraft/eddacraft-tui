**Pre-tag action:** merge #1852 to `main` before `tag.sh` runs.

### A2 — Add Windows trust-model note to CHANGELOG Security

**Source:** security-analyst MINOR #1.

The Windows IPC trust boundary on v0.7.1-beta still relies solely
on the named-pipe DACL set at pipe creation; there is no
client-side post-connect SID equality check (the Unix
`SO_PEERCRED` analogue). This is documented in source at
`crates/anvil-intercept-win32/src/lib.rs:113-120` ("Defence-in-
depth pipe-owner validation on the client side is intentionally
skipped in v1") and is filed as MLP2-051j Draft. Acceptable for
shipping — the same-SID trust posture matches the Unix same-UID
model — but operators reading the CHANGELOG should not infer full
parity with the Unix hardening from a "closed the downgrade-attack
path" line.

**Pre-tag action:** add the following to the v0.7.1-beta CHANGELOG
entry under a new Security subsection (or extend Known Gaps):

> Windows IPC trust on `v0.7.1-beta` relies on the named-pipe
> DACL set at pipe creation. Client-side SID validation
> (defence-in-depth parity with the Unix `SO_PEERCRED` check) is
> tracked as MLP2-051j Draft and will land in a follow-up patch.
> Same-SID processes are inside the v1 trust boundary the same
> way same-UID processes are on Unix.

### A3 — Reword MAX_FUTURE_CLOCK_SKEW CHANGELOG entry

**Source:** security-analyst MINOR #2.

The current CHANGELOG line characterises `MAX_FUTURE_CLOCK_SKEW =
90s` as having "closed a downgrade-attack path". The cap
**bounds** the attack — it does not eliminate it. An attacker who
controls BOTH the daemon's snapshot output AND the workstation
clock (e.g. NTP injection on a misconfigured workstation) can
still slew freshness forward; that scenario is outside Anvil's
threat model but the CHANGELOG should not over-claim.

**Pre-tag action:** replace "closes a downgrade-attack path" with
"bounded at 90 seconds of clock skew" in the CHANGELOG
`MAX_FUTURE_CLOCK_SKEW` bullet, and add one sentence:
"Workstations whose system clock is itself attacker-controlled
remain outside Anvil's threat model."

### A4 — Clarify stop-the-daemon copy in repair hints

**Source:** operations-reviewer MAJOR.

The `StaleHeartbeat` and `AllSurfacesQuarantined` repair hints in
`crates/anvil-cli/src/activation/render.rs:374,377` both include
"stop it (Ctrl-C or kill the process)". `Ctrl-C` is a foreground
interactive gesture; on Windows or in any detached-terminal
scenario, the operator has no actionable non-interactive stop
path because `anvil intercept stop` does not exist.

**Pre-tag action:** replace `(Ctrl-C or kill the process)` with
`(close its terminal, or end the process via Task Manager / kill)`
in both hint strings, and add an entry to the CHANGELOG Known Gaps
section:

> `anvil intercept stop` subcommand does not exist. To stop the
> daemon on Windows, close the terminal or end the process via
> Task Manager; on Unix, Ctrl-C the foreground terminal or
> `kill <PID>`. The missing CLI surface is tracked alongside the
> existing `intercept restart` / `intercept recover` gaps.

The render-hint copy update touches the test file too — the
existing `ready_restart_required_with_stale_heartbeat_points_at_
daemon_start` and `ready_restart_required_with_all_quarantined_
points_at_daemon_restart` tests must be updated for the new
string substring. The judge confirms with the council-reviewer
that this is a copy fix, not a behaviour change, and does not
require a new test.

### A5 — Add Boring Week non-reset note to release record

**Source:** pragmatic-lead MINOR #2.

The release record at `plans/releases/v0.7.1-beta.md` does not
explicitly state that v0.7.1-beta does NOT reset the Wave 5
Boring Week observation window. The `RELEASE-PLAN.md` is
unambiguous on this point — v0.7.1-beta is the named patch-
cadence mechanism for Boring Week blockers; the sit-on claim
graduates on the `v0.7.0-beta` tag's Wave 5 window — but the
release record is the operator-facing artefact.

**Pre-tag action:** add one sentence to the "What ships" section
(or "Risk + rollback"):

> Cutting this patch tag does not reset the Wave 5 Boring Week
> observation window; that window runs on the `v0.7.0-beta`
> baseline and the sit-on claim graduates on the parent tag.

### D2 — Windows E2E test for activation-chain promotion

**Source:** adversarial-reviewer MAJOR #2.

The MLP2-051f hard-gate #5 E2E test
(`end_to_end_against_real_unix_socket_promotes_to_live_validation`)
is `#[cfg(target_os = "linux")]`. A Windows-equivalent integration
test that exercises `promote_to_live_validation_when_daemon_attests`
against a real named pipe via `anvil_intercept_win32::bind_owner_
only_pipe_server` does not exist. MLP2-075's tests
(`windows_query_protection_claim_returns_some/none`) cover the
MCP shim layer but not the activation diagnostic promotion path.
A Windows-specific regression in `query_daemon_status_windows_at_
with_timeout`'s snapshot deserialisation would produce a
permanently-unreachable `Protecting` state on Windows with no
test to catch it.

**Disposition:** defer. File as **MLP2-051k** APS work item Draft
post-merge of this council artefact. The boring-week / patch-tag
risk profile is bounded by the Linux E2E coverage + the MLP2-075
MCP-shim Windows tests + the manual smoke check on Windows the
post-merge plan requires before declaring the user-visible fix
delivered. Not a tag blocker; explicitly named in the Known Gaps.

### D3 — preflight.sh version-match gate

**Source:** adversarial-reviewer MINOR #1.

`scripts/release/preflight.sh` has no gate that compares the
workspace `Cargo.toml` version against the tag being cut. A
release engineer who forgets the version bump would get a green
preflight on a binary that reports the previous tag's version.

**Disposition:** defer. File as a runbook-tooling APS work item
(or GH issue) post-merge of this council. v0.7.1-beta's version
bump landed in PR #1851 and is already on `main`, so this is a
forward-looking improvement, not a blocker for this tag.
