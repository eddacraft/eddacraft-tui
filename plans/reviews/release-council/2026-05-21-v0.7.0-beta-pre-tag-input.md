## Operator-visible observations to surface to the council

1. **Auth-required is harder than the v0.6.x behaviour suggests.** On this box
   the candidate binary refuses `anvil status` and `anvil start` with
   `state: "authRequired"` because the operator's session was revoked
   ("Refresh-token reuse detected"). The existing `[Unreleased]` CHANGELOG
   describes new auth surfaces but doesn't call out **"action commands now
   block on `anvil auth login`"** as a user-facing migration step. Council
   should decide: is this a CHANGELOG addition / migration runbook entry, or
   is the behaviour already documented adequately?

2. **`anvil-run` ↔ daemon IPC gap.** `session.report_process` is called by
   `anvil-run` but the daemon answers `Method not found`. Behaviour is
   recoverable (launcher continues) but the JSON-RPC error is logged as a
   warning to stderr. Decide: ship-with-doc, fix-before-tag, or
   defer-with-issue.

3. **Workspace version still `0.6.2-beta`.** Both `Cargo.toml` workspace
   `version = "0.6.2-beta"` and `package.json` root `"version": "0.6.2-beta"`
   need to be bumped to `0.7.0-beta` before `scripts/release/tag.sh` will
   accept the tag (it gates on `package.json` version match at line 222–224).
   Four internal `packages/*/package.json` files also at `0.6.2-beta`
   (kindling-integration, adapters, edda-stack, aps) typically track the
   binary; four others on independent versions stay put. Plan: single
   `chore(release):` commit bundling this with the CHANGELOG header rename
   after the council pass clears.

4. **CHANGELOG `[Unreleased]` already carries the Known Gaps for
   #1674/MLP2-070 and #1722/MLP2-071** from the 2026-05-20 council pass. No
   new Known Gaps from §3–§11 above; the council should decide whether
   today's auth-required behaviour merits one too.

5. **The 2026-05-20 council file is preserved as historical evidence** per

   carry forward without re-litigation:

  --findings plans/audits/2026-05-21-clawpatch-v0.7.0-beta.json \
