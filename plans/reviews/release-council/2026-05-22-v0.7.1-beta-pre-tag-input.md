## Operator-visible observations to surface to the council

1. **GH [#1831](https://github.com/eddacraft/anvil-001/issues/1831)
   was auto-closed by MLP2-075 (PR #1836) on merge — BEFORE the
   user-visible fix (MLP2-051f) merged.** The original Windows +
   Scoop + PowerShell reporters are still hitting the bug on the
   published `v0.7.0-beta` binary because their version pre-dates
   both fixes. `v0.7.1-beta` is the tag that actually delivers the
   fix to them; the original issue stayed CLOSED through the
   #1840 merge. Council should decide: does the closed-status need
   adjusting (re-open and re-close at tag publish?), or is a
   CHANGELOG cross-reference + post-publish comment on #1831
   sufficient?

2. **Pre-existing AP-008 test failure on `main`
   (`antipattern::patterns::tests::retired_html_css_patterns_are_absent`).**
   PR #1820 reused the AP-008 identifier for TypeScript eval while
   the retired-HTML/CSS hardcoded list still contains AP-008.
   Documented in MLP2-075's post-merge plan. Not introduced by
   this PR. Already noted as deferred in CHANGELOG known-gaps;
   council should decide whether to demote from Known Gaps to a
   regular CHANGELOG `Fixed` once the tracking issue is filed and
   prioritised.

3. **`anvil intercept restart` and `anvil intercept recover` do
   not exist as subcommands.** The MLP2-051f hardening render
   hints (post-Copilot review) now route around this gap by
   pointing at `anvil intercept start --foreground` (cross-
   platform restart) and `anvil intercept unblock --worktree <PATH>`
   (Linux only). The Known Gaps section of the CHANGELOG names
   both gaps explicitly. Council should confirm the documented
   Linux-only `unblock` posture is acceptable for shipping; the
   Windows peer-cred work is filed as MLP2-051j / MLP2-028.

4. **Workspace version bumps + Cargo.lock + 4 internal
   `packages/*/package.json` files were already bundled in PR
   #1851.** No separate prep commit needed at tag time — the
   `scripts/release/tag.sh` version-match gate (line 222-224) will
   succeed against the current `main` HEAD. The
   `Acknowledgements freshness` workflow did not fire on PR #1851
   because no `Cargo.lock` dep additions / removals landed —
   workspace version bumps only.

5. **Clawpatch posture.** No fresh clawpatch sweep was run for
   this patch tag. The justification is that the
   `v0.7.0-beta..HEAD` diff is dominated by:
   - APS narrative + docs/spec updates (no production code paths)
   - The activation-daemon-evidence work-set (already vetted via
     1 full Council + 2 Mini Councils + 5 Copilot rounds —
     adversarial / security personas were on every panel)
   - MLP2-069 IO-outage variant (10-line code change, regression
     test pinned in same PR)
   - DOCGOV docs validation (governance scaffolding, no runtime
     impact)

    Council should explicitly affirm or override this posture. If a
    fresh sweep is required, candidate output lands at
    `plans/audits/2026-05-22-clawpatch-v0.7.1-beta.json` and the
    council re-pass is scoped at `--limit 10` rather than the full
    backlog.
