## Change under review

FLAGCAT-012..014 land together: host-owned two-set completeness, bidirectional
operational-flag linkage, and a generated catalogue view. The protected
`ipc.rs` delta adds a catalogue-governed method registry, classifies telemetry
subscribe/unsubscribe through that registry, and admits client-to-daemon
methods from it. `DeliveryVisibility` is catalogue metadata, not an ACL.
Dispatch still uses the original wire spelling so aliases keep existing
parameter and error behaviour.

## Findings

### In-contract major — fixed

- general: `CANONICAL_GOVERNED_METHODS` was a shadow inventory; session,
  telemetry, and unblock methods could be added to dispatch without updating
  it. **Fixed:** `handle_jsonrpc_request` rejects ungoverned methods, telemetry
  classification already uses `resolve_governed_method`, and
  `governed_registry_is_the_live_client_to_daemon_admission_set` source-scans
  the live dispatch sites.

### In-contract minor — fixed

- general: FLAGCAT-013 docs still described linkage as future work. **Fixed:**
  add-a-flag procedure and JSON example require `controlsProductFeatures`.

### Later / advisory (not must-fix)

- adversarial: CLI flag-style locators and collapsed nested Clap leaves remain
  host-owned projections per the spec, not a completeness hole.
- adversarial: exclusion plus host reclassify is exactly the two-set contract;
  union-only comparison is invalid by spec.
- adversarial: serde omit of `controlsProductFeatures` still deserialises to
  `[]` on older payloads; TS loader and kernel-types codegen fail loud on
  missing arrays. Follow-up if runtime Rust JSON loading must match.
- operations residual: a JSON-only catalogue PR still does not run
  `docs:check`; the flags-catalogue unit test is the catalogue-class pin.
