# LANGTS external false-positive dogfood

Date: 2026-06-18

Target: the TypeScript / JavaScript anti-pattern catalogue (LANGTS family, rules
`AP-*` and `GS-001`) run against a diverse external open-source corpus, to
compute a genuine false-positive (FP) rate for the council §16.5 #9 bar on code
Anvil did not write. This mirrors the internal `RSTLAN-008` Rust dogfood
(`plans/reviews/2026-06-05-rstlan-008-t3-dogfood.md`) and its external sibling
(`plans/reviews/2026-06-18-rstlan-external-fp.md`), but on unfamiliar
third-party TS/JS. The LANGTS family shipped with **no** external multi-repo FP
run — this is its first.

Reproduce:

```text
# Scan dumps already generated by the external-fp harness (do NOT re-run here):
#   scripts/dogfood/external-fp  →  /home/aneki/.cache/anvil-ext-fp/out/<repo>.{default,optin}.json
# Source-joined worksheet:        /home/aneki/.cache/anvil-ext-fp/out/langts.worksheet.md
# Corpus + pinned SHAs:           scripts/dogfood/external-fp/corpus.json  (group "langts")
# Each finding classified against its source line by reading the cloned repo at
# the pinned SHA, and — for GS-001/AP-003 — by replaying the scanner's
# comment/string/regex masker (crates/anvil-checks/src/antipattern/mask.rs)
# over the file so the classification matches what the scanner actually saw.
```

Rule engine source of truth: `crates/anvil-checks/src/antipattern/scanner.rs`
and `patterns/compiled/registry.json`.

## False-positive analysis (§16.5 #9, default AP-\* / GS-\* only)

Method: every cluster was pattern-detected over the JSON dump joined to source,
then ground-truthed by reading the cited lines. For GS-001 and AP-003 the
scanner's masker (`mask.rs`) was replayed over each finding's file so the
classification reflects the masked view the scanner actually matched against
(strings, line/block comments and regex literals blanked; template literals
passed through — see below). Idiomatic-but-genuine matches are **true positives
with a noise note**, not FPs.

### Per-rule classification

**AP-003 explicit `any` — 1,386 findings, 0 FPs (true positives, noise note).**
The registry regex is `:\s*any\b|as\s+any\b|<any>` — well anchored. Replaying it
over every finding's masked file reproduced the scanner's exact counts
(885 / 175 / 326) and resolved into three arms only: `: any` annotations,
`as any` casts, and `<any>` generic type args (e.g.
`ComponentType<any>` `packages/docs/app/blog/[slug]/page.tsx:14`,
`Promise<any>` `packages/vite/src/module-runner/esmEvaluator.ts:22`,
`Emitter<any>` `packages/common/src/appEventBus.ts:36`). **Zero
substring/identifier FPs**: the `\b` anchor and the `: `/`as `/`<` prefixes mean
`anyOf`, `many`, `anyway`, `Company` never match — verified against zod's
`manySuite`/`many` identifiers in `packages/zod/src/v3/benchmarks/union.ts`,
which carry no AP-003 finding. zod's 885 hits are real (`as any` is structural in
its type machinery, e.g. `packages/bench/metabench.ts:85 bench.add(name, fn as any)`) —
genuine matches, just high-density. **Noise note**, not FP.

**GS-001 non-null assertion — 689 findings, 8 FPs.** A >50-finding cross-repo
sample (and a full masker replay) confirms the overwhelming majority are real
non-null assertions: `foo!.bar`, `arr[i]!`, `map.get(k)!`, `expr!` —
e.g. `hotMap.get(server.environments.client)!` `packages/vite/src/node/server/hmr.ts:593`,
`req.url!` `static.ts:218`, `chunk.viteMetadata!` `build.ts:1494`. The base
regex `[\w.)\]]+!` + trailing-byte filter (`.[(;,)`/whitespace/EOL) correctly
rejects the overloaded `!`: logical-not `!foo` never matches (no `[\w.)\]]`
before `!`); inequality `!=`/`!==` is rejected because the byte after `!` is `=`
(not in the trailing set); and `!`/`any` inside `"…"`/`'…'` strings, `//`/`/*…*/`
comments and `/…/` regex literals are blanked by the masker before matching
(confirmed by the existing `gs001_does_not_fire_on_bang_inside_string_literal`
etc. tests). The genuine FPs all share one root cause — **the masker passes
template literals (backticks) through unmasked** (mask.rs lines 18–22, a
deliberate trade-off so `${…}` interpolation code keeps being scanned), so a `!`
in *template literal text* is matched as if it were code:

| FP | repo:file:line | source | sub-class |
| -- | -------------- | ------ | --------- |
| 1 | zod `packages/docs/components/gold.tsx:54` | `` className={`my-0! object-contain dark:hidden ${…}`} `` | Tailwind `!important` |
| 2 | zod `packages/docs/components/gold.tsx:59` | `` className={`my-0! object-contain hidden dark:block ${…}`} `` | Tailwind `!important` |
| 3 | zod `packages/docs/components/hero-logo.tsx:16` | `` className={`… mx-auto my-0! transition-opacity …` `` | Tailwind `!important` |
| 4 | zod `packages/docs/components/hero-logo.tsx:30` | `` className={`… mx-auto my-0! transition-opacity …` `` | Tailwind `!important` |
| 5 | vite `packages/vite/src/node/utils.ts:478` | `` `offset is longer than source length! offset ${offset} …` `` | prose `!` |
| 6 | excalidraw `packages/excalidraw/subset/woff2/woff2-bindings.ts:534` | `` `… on the asm.js/wasm heap! (Valid unicode …)` `` | prose `!` |
| 7 | excalidraw `…/woff2/woff2-bindings.ts:670` | `` `Stack overflow! Stack cookie has been overwritten …` `` | prose `!` |
| 8 | excalidraw `…/woff2/woff2-bindings.ts:683` | `` `Stack overflow! Attempted to allocate ${allocSize} …` `` | prose `!` |

Two sub-classes: (a) the **Tailwind `!important` modifier** in a `className`
template (`my-0!`, `mx-auto`-adjacent utilities — Tailwind v3.4+ moved the
`!` suffix to the end of the class); (b) **prose exclamation marks** in
template-literal error messages. Note that a `!` inside a *multi-line* `${…}`
interpolation (e.g. `appstate!.offsetLeft` across
`examples/.../ExampleApp.tsx:411-412`, `elementWithCanvas.canvas!.width`
`packages/element/src/renderElement.ts:687`) is a **true positive**: it is a
real non-null assertion that the unmasked template happens to expose, so the
verdict is correct even though the masker is not tracking the interpolation
boundary.

**AP-015 Zod escape hatch — 50 findings (zod only), 0 FPs.** All real `z.any()`
/ `.passthrough()` calls (e.g. `from-json-schema.ts:254 return z.any()`,
`object.test.ts:93 …passthrough().parse(data)`). Many sit in `*.test.ts`
fixtures — genuine matches; AP-015 carries no test allowlist, so they count.
Noise note (heavy in a schema library by nature), not FP. The `anyOptional`
identifier at `object.test.ts:259` is correctly **not** flagged (no substring
FP).

**AP-004 `@ts-ignore` — 61 findings, 0 FPs.** All real directives, including
zod's `/** @ts-ignore Cast variance */`, vite's `.d.ts` "may not be installed"
guards, and excalidraw `.test.tsx` ignores. Masking is correct — these live in
comments and AP-004 is intentionally *not* code-scoped, so the comment text is
matched on purpose.

**AP-006 empty catch — 31 findings, 0 FPs.** All real `catch (e) {}` /
`catch (_err) {}` (e.g. zod benchmark `discriminatedUnion.ts:46`,
excalidraw `App.tsx:876`). No string/comment FP.

**AP-009 `new Function` — 4 findings, 0 FPs.** All four read as real dynamic
`new Function(string)`: `vite ssrStacktrace.ts:13 new Function('throw new Error(1)')()`,
`vite utils.ts:1680 new Function(\``, `excalidraw woff2-bindings.ts:1345`,
`excalidraw woff2-bindings.ts:2065 new Function("dynCall","rawFunction",body)`.
No "class named Function" / string / comment FP.

**AP-008 `eval()` — 0 findings.** Nothing to classify (clean negative across the
corpus).

**AP-001 broad `eslint-disable` — 7 findings, 0 FPs.** All real whole-file
`/* eslint-disable */` at the top of vendored / wasm-generated files
(`vite playground/.../slash@3.0.0.js:1`, `excalidraw polyfill.ts:4`,
`harfbuzz-wasm.ts`, `woff2-bindings.ts:1`). Genuine matches; these are exactly
the "the whole file opts out of linting" signal AP-001 targets.

**Genuine-FP rate on the default TS/JS catalogue: 8 / 2,228 = 0.36%.** Every FP
is GS-001, and every one traces to the single masking gap (template-literal text
is unmasked). This is comfortably inside the spirit of the §16.5 #9 bar
(RSTLAN-008 set the precedent at 0%; the unmasked-template trade-off is
documented in `mask.rs` and is a deliberate false-positive-over-false-negative
choice).

### Proposed fix — GS-001 template-text FPs

Root cause: `mask.rs` `S::Template` passes every character through and only
exits on a closing backtick; it does not lex `${…}` interpolation, so it cannot
tell "real interpolation code" (must stay scanned) from "literal template text"
(should be masked for code-scoped rules). The safe, low-risk fix is to **mask
template-literal text while keeping `${…}` interpolation spans unmasked**: track
an interpolation depth inside `S::Template` (`${` → enter code, matching `}` →
back to template text), blanking only the literal-text runs. This removes both
sub-classes (Tailwind `!important` and prose `!`) without re-introducing the
false-negatives the current unmasked behaviour was protecting against, because
the real assertions in `${…}` stay visible.

- **Crate/file:** `crates/anvil-checks/src/antipattern/mask.rs`
  (`mask_line` / the `S::Template` arm; add an interpolation-depth counter and a
  `Carry::TemplateInterp` carry variant for multi-line `${…}`).
- **Cheaper alternative** (if interpolation lexing is deemed too invasive for
  this tuning pass): keep template text unmasked but add a GS-001 post-filter
  that rejects a match whose `!` is **immediately followed by whitespace AND
  preceded by a token that is a known CSS-utility/Tailwind class or a
  natural-language word inside a backtick run**. This is narrower and risks the
  occasional real `foo! bar` assertion, so the masker fix is preferred.
- **Regression-fixture target:** `crates/anvil-checks` masker unit tests
  (`mask.rs` `#[cfg(test)] mod tests`) — add `` `my-0! text-sm` `` (Tailwind)
  and `` `Stack overflow! ${x}` `` (prose) cases asserting GS-001 does **not**
  fire, plus a guard that `` `${ map.get(k)! }` `` (interpolation) **still**
  fires. Mirror in `tests/scanner-parity/fixtures.json` so the Rust and TS
  scanners stay aligned.

## Cross-cutting observations (out of the §16.5 TS/JS FP rate)

### Secret detection — high FP, scoped out of this rate

The `SECRET-*` checks (a separate detector, not the AP-*/GS-* catalogue) are
almost entirely false positives on this corpus and should be treated as a
distinct tuning track:

- **SECRET-CREDIT-CARD — 119 (excalidraw) + 10 (zod).** Worst offender. In
  excalidraw it fires on **floating-point coordinate arrays** in drawing
  fixtures (`dev-docs/src/initialData.js`, `examples/.../initialData.tsx`,
  e.g. `[3.5475921483286084, -47.099726468136254]`) and on integer literals like
  `9999999999999999` / `9007169...` — a 16-digit / Luhn-ish numeric heuristic
  with no field-name or quoting context. zod's are test fixtures
  (`"1234-5678-9012-3456"`) and `9007199254740991` (`Number.MAX_SAFE_INTEGER`).
  All FPs.
- **SECRET-HIGH-ENTROPY-STRING — 25 (zod) + 6 (excalidraw).** base64 test
  vectors (`"TWFueSBoYW5kcyBtYWtlIGxpZ2h0IHdvcms="`), alphabet/charset constants
  (`"abcdefghijklmnopqrstuvwxyz"`), and URLs with query params. All FPs.
- **SECRET-DATABASE-URL — 10 (zod).** Zod's connection-string *validator test
  cases* (`"mongodb://username:password@host:1234"`) and template-literal type
  patterns. All FPs.
- **SECRET-JWT-TOKEN — 2 (zod).** JWT *test vectors* in `string.test.ts`. FP.
- **SECRET-API-KEY — 1 (excalidraw).** Literal placeholder
  `"excalidraw-oai-api-key"`. FP.

Observation: the secret detector lacks the context-gating the AP-*/GS-* rules
have (no comment/string masking awareness, no test/fixture allowlist, no
field-name proximity for card/URL patterns). It would benefit from the same
fixture-allowlist + numeric-literal-vs-formatted-secret discrimination the Rust
side already discussed. Tracked as its own observation; **not** folded into the
TS/JS catalogue FP rate per the analysis scope.

### Debt-comment hygiene (DD-001/002/003) — language-agnostic, not LANGTS

`DD-001` (TODO/FIXME) 4 / 28 / 97, `DD-002` (HACK/XXX) 0 / 0 / 1, `DD-003`
(temporary/workaround) 0 / 1 / 0. Spot-checked: all real debt comments
(`// TODO: remove this when we don't support Node 20`,
`// HACK: Disable transform handles …`). These are working as designed and the
SPG-003 escape-hatch lookarounds (`[A-Z]+-\d+`/`#\d+`/`issue`/`ticket`) correctly
suppress comments that already reference a tracker. Not part of the TS/JS
catalogue; excluded from the FP rate.

## Verdict

**LANGTS passes the §16.5 #9 FP bar on an external TS/JS corpus.** Zero scanner
panics across ~345k LOC / 2,986 files; a **0.36% genuine-FP rate (8 / 2,228)**
on the default AP-*/GS-* catalogue, with every FP attributable to one
well-understood masking gap (template-literal text is unmasked) and a concrete,
low-risk fix proposed in `mask.rs`. AP-003 (the largest cluster, 1,386) is
exactly anchored with no substring FPs; AP-009/AP-001/AP-004/AP-006/AP-015 are
all clean. The opt-in rules behave correctly and their volumes validate the
opt-in decision. The secret detector is a separate, high-FP track worth its own
tuning pass but is correctly out of scope here.
