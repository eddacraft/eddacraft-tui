# RUSTNX Completion — hakari, cargo-deny, third-party attribution

Design for the final two work items in the `rust-nx-migration` APS module
(RUSTNX-008, RUSTNX-009) plus a closely-related attribution deliverable that
falls out of RUSTNX-009's licence work.

> **Shipped implementation note (2026-04-24, PR #1067)**
>
> What landed differs from the original design in one notable way: the
> attribution artefact is **`ACKNOWLEDGEMENTS.md` at repo root**, not
> `THIRD_PARTY_NOTICES.md` /
> `crates/anvil-cli/resources/third-party-notices.md` as described below.
> The file carries a hand-curated thanks section above a marker-delimited
> auto-generated block produced by `tools/generate-acknowledgements.sh`,
> which wraps `cargo about generate` scoped to `crates/anvil-cli/Cargo.toml`
> (so dev-deps are excluded). `anvil licenses` embeds the whole file via
> `include_str!`. The CI freshness job is named `acknowledgements-diff`,
> not `about-diff`. The release pipeline also publishes `ACKNOWLEDGEMENTS.md`
> to `eddacraft/anvil` main branch per release.
>
> The rest of this design (hakari, cargo-deny, `anvil licenses` command
> shape, CI version pinning) matches what shipped.

## Goals

1. **RUSTNX-008** — unify feature resolution across the Rust workspace so
   per-crate builds share dependency compilations, via `cargo-hakari`.
2. **RUSTNX-009** — enforce licence/advisory/ban policy on every Rust PR, via
   `cargo-deny`.
3. **Attribution artefact** — generate a `THIRD_PARTY_NOTICES.md` file from
   cargo metadata, keep it in git, enforce freshness in CI, and expose its
   contents at runtime via an `anvil licenses` CLI command.

## Non-Goals

- Attribution for TypeScript dependencies. `anvil` is a Rust binary; the
  cargo graph is exhaustive for what ships. TS-side attribution is a
  separate future initiative.
- Replacing `cargo audit` or `cargo outdated` — those stay as-is.
- Nightly-toolchain-only features (e.g. `cargo udeps`).
- Any change to crate boundaries, lint levels, or `rustfmt.toml`.

## Architecture

```
workspace root
├── crates/
│   ├── workspace-hack/            (new, RUSTNX-008)
│   │   ├── Cargo.toml             generated by `cargo hakari generate`
│   │   └── src/lib.rs             empty re-exports
│   └── anvil-cli/
│       ├── resources/
│       │   └── third-party-notices.md   (generated, committed)
│       └── src/commands/
│           └── licenses.rs        (new, reads via include_str!)
├── deny.toml                      (new, RUSTNX-009)
├── about.toml                     (new, attribution)
├── about.hbs                      (new, handlebars template)
├── .config/hakari.toml            (new, hakari config)
└── .github/workflows/rust.yml     (extended — deny + hakari verify + about --diff)
```

### RUSTNX-008 — `cargo-hakari`

- Create `crates/workspace-hack/` with `publish = false`, added to the
  workspace `members` list.
- `.config/hakari.toml` configures the hack crate name, resolver v2, and the
  target triples we care about (`x86_64-unknown-linux-gnu`,
  `aarch64-apple-darwin`, `x86_64-pc-windows-msvc` match the cross matrix).
- Every existing workspace member gets `workspace-hack = { path =
  "../workspace-hack" }` as a `[dependencies]` entry so feature unification
  takes effect for normal builds.
- CI adds a `hakari-verify` step in `rust.yml` that runs
  `cargo hakari verify` and `cargo hakari generate --diff` — the latter fails
  the build if the committed manifest is stale.
- `cargo-hakari` is installed via `taiki-e/install-action` (SHA-pinned,
  version tracked in a new `CARGO_HAKARI_VERSION` env, same pattern as
  `CARGO_NEXTEST_VERSION`).

### RUSTNX-009 — `cargo-deny`

`deny.toml` policy:

| Section | Setting | Value |
|---|---|---|
| advisories | `vulnerability` | deny |
| advisories | `unmaintained` | warn |
| advisories | `yanked` | deny |
| advisories | `notice` | warn |
| licenses | `confidence-threshold` | 0.93 |
| licenses | `allow` | MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, BSD-2-Clause, BSD-3-Clause, ISC, Unicode-DFS-2016, Unicode-3.0, CC0-1.0, Zlib, MPL-2.0 |
| licenses | `copyleft` | deny |
| bans | `multiple-versions` | warn |
| bans | `wildcards` | deny |
| sources | `unknown-registry` | deny |
| sources | `unknown-git` | deny |

Allowlist is derived from the current lockfile. If any current dep violates,
we either add it to `exceptions` with justification or swap the dep.
`workspace-hack` is added to `[bans.skip]` so hakari's aggregation doesn't
trip the multiple-versions check.

CI adds a new `deny` job in `rust.yml` (parallel, behind the shared
rust-cache). Same SHA-pinned install pattern.

### Attribution — `THIRD_PARTY_NOTICES.md` + `anvil licenses`

**Generation:**

- `about.toml` shares the licence allowlist with `deny.toml`; both files are
  hand-kept with a comment cross-referencing each other. Derivation via a
  helper script is deferred until drift proves painful.
- `about.hbs` is a minimal handlebars template emitting per-crate sections
  with name, version, licence, source URL, and the full licence text.
- `cargo about generate about.hbs -o crates/anvil-cli/resources/third-party-notices.md`
- File is committed. CI runs the same command and `git diff --exit-code` —
  stale output fails the build.

**Runtime exposure (`anvil licenses`):**

- New subcommand under `anvil-cli`, file `src/commands/licenses.rs`.
- `include_str!("../../resources/third-party-notices.md")` at compile time
  so the binary is self-contained; no runtime file deps.
- Output:
  ```
  Anvil <version>
  Copyright (C) 2026 EddaCraft. All rights reserved.
  Licensed under LicenseRef-Proprietary.

  Third-party dependencies:

  <contents of third-party-notices.md>
  ```
- Styling: bold headers only, no colour (muted-palette request). Respect
  `NO_COLOR` — plain output in pipes.
- Flag `--format <plain|markdown>`:
  - `plain` (default): stripped markdown, straight to stdout
  - `markdown`: raw markdown source, useful for piping to a printer or PDF
- Exit 0, no network, no side effects.

## Error Handling

- `cargo hakari generate --diff` non-zero → CI failure with the
  missing/changed dependency surfaced.
- `cargo deny check` non-zero → fails the PR with the offending crate +
  licence/advisory + exception suggestion.
- `cargo about generate --diff` non-zero → prints the offending diff and
  points the contributor at `pnpm run licenses:generate` (new root script).
- `anvil licenses` runtime failure is unreachable — `include_str!` is
  compile-time.

## Testing Strategy

- **Unit tests** on `anvil licenses`:
  - Snapshot test that the output includes the `Licensed under
    LicenseRef-Proprietary` header.
  - Assert `--format markdown` output matches the embedded file byte-for-byte.
  - Assert `NO_COLOR=1` output contains no ANSI escape sequences.
- **CI validation:**
  - `hakari-verify` fails when a crate's deps are edited without running
    `cargo hakari generate`.
  - `deny` fails when a new dep with a copyleft licence is added.
  - `about-diff` fails when `cargo about generate` output would change.
- **Manual smoke test** on this branch:
  - Run each CI step locally before pushing.
  - Confirm the generated notices file is coherent and reproducible.
  - Run `anvil licenses` end-to-end and inspect output.

## Rollout

Single PR into `dev` containing all three deliverables. Items are coupled:
hakari introduces a crate that deny has to know about, and the attribution
file and `anvil licenses` command are independently reviewable but share the
handlebars template. Splitting would create awkward intermediate states.

Commit sequence:
1. `chore(ci): add cargo-hakari workspace-hack (RUSTNX-008)`
2. `chore(ci): add cargo-deny licence/advisory gate (RUSTNX-009)`
3. `feat(anvil-cli): add licenses command with third-party attribution`
4. `docs(aps): mark RUSTNX complete, archive module`

## Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Hakari hack crate trips `cargo deny bans.multiple-versions` | Add it to `[bans.skip]` in `deny.toml` from day one |
| A current dep has a licence not in the allowlist | Run `cargo about generate --print-licence-list` before merging; add to `exceptions` or swap the dep |
| `include_str!` bloats anvil-cli binary | Notices file expected ~200 KB for the current dep set; anvil-cli binary is already multi-MB, rounding error |
| `about.hbs` and `deny.toml` allowlists drift | Cross-reference comment in each file; future optimisation is a generated `about.toml` from `deny.toml` |

## Open Questions

None blocking. All decisions confirmed in brainstorming:

- Hakari mode: `publish = false` workspace-hack crate.
- Deny severities: `vulnerability=deny`, `unmaintained=warn`, `yanked=deny`,
  `notice=warn`.
- Copyleft: `deny`.
- Colour: bold-only headers, no ANSI colour. Respect `NO_COLOR`.
- Attribution scope: Rust cargo graph only; TS deps deferred.
