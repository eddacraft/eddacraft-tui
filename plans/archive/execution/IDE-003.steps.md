## Intent

When CLI-based operations (gates, validation) return warnings, the extension
accurately maps file paths, line numbers, and columns to VS Code diagnostic
locations. Clicking any warning navigates to the correct position.

## Prerequisites

- [ ] CLI outputs JSON with structured location data
- [ ] DiagnosticsManager exists with basic mapping

## Steps

### 1. Audit CLI JSON output format

- **Checkpoint:** Document expected fields: file, line, column, endLine,
  endColumn
- **Pattern:** `cli/src/commands/` — validate/gate command output

### 2. Handle relative vs absolute paths

- **Checkpoint:** Relative paths resolve correctly to workspace files
- **Validate:** CLI returns `src/foo.ts`, extension opens correct file

### 3. Map 1-indexed CLI output to 0-indexed VS Code

- **Checkpoint:** Line/column offset handled consistently
- **Pattern:** `packages/vscode-extension/src/services/diagnostics.ts`

### 4. Support range highlighting (not just point)

- **Checkpoint:** Multi-character/line ranges highlighted when available
- **Validate:** ESLint warning highlights entire problematic expression

### 5. Handle missing location gracefully

- **Checkpoint:** Warnings without location appear at file start, not crash
- **Validate:** Gate result with no line number shows at line 1

### 6. Test with all gate types

- **Checkpoint:** Lint, coverage, secrets, architecture warnings navigate
  correctly
- **Validate:** Run each gate type, click resulting warnings

## Completion

- [ ] All checkpoints validated
- [ ] Task marked complete in source module
- [ ] All warning types navigate to correct location
- [ ] No crashes on malformed location data
