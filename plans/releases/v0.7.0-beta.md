## What ships

`v0.7.0-beta` carries the daemon-working product slate — the
`v0.7.0-beta` window's "Let's Use This" claim from
[`RELEASE-PLAN.md`](../../RELEASE-PLAN.md).

**Two-level claim** (per the 2026-05-17 amendment):

1. **Tag-time claim** (applies the moment `v0.7.0-beta` is cut): _Anvil
   protects this project end-to-end through the daemon, hooks, witness
   chain, baseline, and wrapped agent launch surfaces, with protection
   posture legible during sustained use and a signature-verified update
   path to every install method._ Verifiable from code state alone —
   every tag-time-claim gate listed below is a checkable artefact.
2. **Sit-on claim** (graduates post-tag, after Wave 5 Boring Week
   confirmation): _Anvil is ready to live on a senior engineer's
   machine for a month without being uninstalled._ The
   release-notes / web-copy update on the existing `v0.7.0-beta` tag
   graduates the claim — no re-tag required. A single blocker surfacing
   in Wave 5 cuts `v0.7.1-beta` on the existing `-beta` patch cadence.

## Source-SHA / branch-strategy note

Unlike `v0.6.3-beta`, `v0.7.0-beta` cuts from `main` directly — the
operating-model substrate (OPMODEL / RELORCH / CICD) and the WATCHUX
hotfix lane are all behind us. `main` is the source of truth and the
green CI SHA at cut time is the candidate.

APS reconciliation rule 3 (`source.commitSha` reachable from the release
tag) is satisfied by the tag pointing directly at the cut SHA.

## Post-tag steps

1. Update `lifecycleState` `candidate` → `published`.
2. Fill in `source.commitSha`, `artifacts`, `verification`,
   `trackingIssue`, `releases.{private,public}.url`, and
   `aps.reconciledAt` from the cut output.
3. Advance the `[Unreleased]` section in `CHANGELOG.md` to
   `[0.7.0-beta] — <YYYY-MM-DD> — Daemon-Working End-to-End Protection`.
4. Run the APS cleanup sweep to advance every `Merged` item in the items
   list to `Released/Shipped`.
5. Start Wave 5 Boring Week per the
   [release plan](../../RELEASE-PLAN.md#wave-5-boring-week-validation-gate)
   protocol. Outcome decides whether the sit-on claim graduates on this
   tag, slips to `v0.7.1-beta`, or yanks.
