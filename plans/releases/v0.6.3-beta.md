## What shipped

Patch release for beta-user first-run and watch friction reported against
`v0.6.2-beta`. Five APS items, all customer-facing fixes plus one additive
escape-hatch command:

- `WATCHUX-001` Homebrew-aware curl installer preflight
- `WATCHUX-002` Shared local-noise ignore policy for audit/watch
- `WATCHUX-003` Initial watch scan as baseline state, not new violations
- `WATCHUX-004` Immediate watch startup feedback + non-TTY fallback
- `ADOPT-005` `anvil uninstall` command (project-scoped, `--global` for
  user-level)

No new APIs, no breaking changes. Full body in
[`CHANGELOG.md`](../../CHANGELOG.md#063-beta--2026-05-15--beta-watch-ux--uninstall-hotfix).

## Source-SHA / branch-strategy note

The tag was cut from `hotfix/v0.6.3-watchux-uninstall` tip rather than `main`
because equivalent commits were already on `main` via PR #1497 + PR #1521 but
`main` also carried 232 commits of unrelated in-flight work that must not ship
in a patch release. Operator authorised this path on the tracking issue;
follow-up encoded in `tag.sh --hotfix` flag via PR #1590. The hotfix branch is
deleted post-release; the tag is the sole ref keeping `67ca658d` alive.

APS reconciliation rule 3 (`source.commitSha` reachable from the release tag)
is satisfied: the tag points directly at `67ca658d`.
