## Answer (summary)

A workspace opts in to GCTX source-snippet egress with an explicit operator action, not a repo-controlled file. The product command is `anvil gctx egress enable` (confirmation, or `--yes` non-interactively). That writes per-workspace consent under operator-owned state (`$ANVIL_HOME/gctx-egress/`, else `$XDG_STATE_HOME/anvil/gctx-egress/`, else `~/.local/state/anvil/gctx-egress/`), keyed by workspace path. `anvil gctx egress status` reports the effective decision and source (`env` / `config` / `default`); `anvil gctx egress disable` removes consent and returns to identity-only. Consent is never taken from a worktree path; the legacy `anvil/witness/gctx-egress.json` record is not honoured (`crates/anvil-intercept/src/egress_consent.rs`). Snippets still require a second gate on the request: only `anvil_symbol_context` can emit source text, and only when `includeSource: true` is set. Either gate missing yields identity-only locations (and a `snippetEgressHint` if source was requested while egress is off). See `docs/guides/ai-context-delivery.md` and `crates/anvil-cli/assets/skills/anvil-developer-functions/references/tool-reference.md`. Process env `ANVIL_GCTX_EGRESS` overrides persisted consent on every call (`crates/anvil-gctx-types/src/lib.rs` `resolve_snippet_egress`): unset uses persisted consent; `1` permits snippets for this process (still per-request `includeSource`); `0` is a kill-switch that turns the whole graph-context surface off (`disabled`), not the snippet-safe default. The named flag `gctx.egress` in `flags/manifest.json` has `defaultVariant: "disabled"` (CE-9). If the workspace does not opt in (no consent record, env unset or not `1`): the default is identity-only (PV-9 CE-1). Tools and `graph://` resources still return symbol identities, workspace-relative paths, and edges; they do not return source text. An unreadable consent file fails closed to identity-only. `ANVIL_GCTX_EGRESS=0` is not that default.
