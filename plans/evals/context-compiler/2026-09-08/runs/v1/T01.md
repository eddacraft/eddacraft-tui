## Answer (summary)

Anvil’s MCP surface is two separate halves. Do not treat a graph answer as a write decision. Graph context is read-only projection. Tools and graph:// resources answer questions about the codebase (symbols, dependents, callers, blast radius, neighbourhood) so an assistant can reason from a map instead of reading whole files. They return context, never a decision, and never block. They do not change code. Setup and behaviour live in docs/guides/ai-context-delivery.md. The six identity-only graph tools are anvil_search_symbols, anvil_find_dependents, anvil_find_callers, anvil_impact_of_change, anvil_affected_tests, and anvil_symbol_context. Results are advisory and optional. Launch validation is the pre-write enforcement gate. The user-facing entry point is anvil_validate_write (team shorthand “RMCP validation” names the Rust MCP host, not a second product). Call it before applying a write. It scores the proposed content against secrets, regex anti-patterns, and boundary rules and returns a four-valued decision: block (authoritative — do not write), warn (findings present but enforcement lets the write proceed — surface and continue), gateUnavailable (gate could not run — surface and proceed), allow (passed). crates/anvil-cli/assets/skills/anvil-developer-functions/SKILL.md adds anvil_apply_patch as the lean sibling for unified diffs; honour the same decision table. allow is not proof that anvil check (regex plus AST) would be clean. When to call which: reach for GCTX tools when you need to understand code (locate a symbol, who imports a file, who calls a function, what might break, which tests to run). Reach for anvil_validate_write (or anvil_apply_patch) when you are about to change code. They are complementary: pull graph context to plan an edit, then validate the edit before writing. A typical sequence in the same guide is search → impact → affected tests → edit → anvil_validate_write on the new content. AGENTS.md matches this split: graph-context tools (it also names anvil_status and anvil_query_boundary alongside the six) to understand code, bounded and never blocking; anvil_validate_write / anvil_apply_patch before a write, honouring block and surfacing warn.
