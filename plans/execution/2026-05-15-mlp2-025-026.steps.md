## PR-B — MLP2-026 (Fence-Cascade Mode)

Branch: `feat/mlp2-026-fence-cascade` from `main`. ~5 commits.

### B1. `CascadeRecord` persistence + `RateWindow::new(4, 60s)` on `FenceStore`

- **Checkpoint:** `FenceFile` gains wire-additive `cascades: Vec<CascadeRecord>` (serde defaults; version stays 1). In-memory per-worktree `RateWindow::new(4, Duration::from_secs(60))`. The 5th fire within 60 s returns `Throttle` → engaged-state written and persisted. `is_cascaded()` / `clear_cascade()` accessors exist. Engage path emits notification + `tracing::warn!`; reasons as `pub const`.
- **Validate:** `cargo test -p eddacraft-anvil-intercept --lib fence::tests::{four_fences_in_sixty_seconds_do_not_engage_cascade,five_fences_in_sixty_seconds_engage_cascade,cascade_state_round_trips_through_store_reload}`
- **Commit:** `feat(intercept): MLP2-026 persisted cascade state + rate window`

### B2. Fire-count integration inside `fence_worktree()`

- **Checkpoint:** Each fire records through the rate window; cascade state persists across subsequent fires without re-triggering side effects.
- **Validate:** `cargo test -p eddacraft-anvil-intercept --lib fence::tests::cascade_state_persists_until_acknowledged`
- **Commit:** `feat(intercept): MLP2-026 fence-fire records through cascade window`

### B3. Status surface update

- **Checkpoint:** `WorktreeStatus` and `WorktreeStatusV1` gain `cascaded: bool` and `cascade_since: Option<u64>`. `render_status` renders the `cascade:` line when applicable.
- **Validate:** `cargo test -p eddacraft-anvil-intercept --lib status::tests::cascaded_worktree_surfaces_in_status_json`
- **Commit:** `feat(intercept): MLP2-026 status surface cascade fields`

### B4. Registry refusal on cascaded worktrees

- **Checkpoint:** `SessionRegistry::register()` consults `FenceStore::is_cascaded(&path)` under documented lock ordering (cascade-before-registry); new `RegistryError::WorktreeCascaded { worktree }` variant.
- **Validate:** `cargo test -p eddacraft-anvil-intercept --lib registry::tests::register_on_cascaded_worktree_is_refused`
- **Commit:** `feat(intercept): MLP2-026 register refuses cascaded worktrees`

### B5. IPC `UnblockCascade` with `OperatorContext` + CLI subcommand — `mini` Council before push

- **Checkpoint:** Wire-additive `IpcCommand::UnblockCascade { worktree, operator: Option<OperatorContext> }` variant + `OperatorContext { uid, pid, hostname }`. Daemon handler populates `operator` from IPC peer credentials, calls `clear_cascade()`, resets the window, emits notification + `tracing::info!` with the operator context. CLI `anvil intercept unblock --acknowledge-cascade <worktree>` canonicalises path before dispatch.
- **Validate:** `cargo test -p eddacraft-anvil-intercept --lib {ipc::tests::unblock_cascade_round_trips_with_operator_context,fence::tests::acknowledge_cascade_resets_rate_window}` and `cargo test -p eddacraft-anvil-cli --lib commands::intercept::tests::unblock_acknowledge_cascade_dispatches_ipc`
- **Council:** `/council mini` against changed crates (`anvil-intercept`, `anvil-intercept-proto`, `anvil-cli`).
- **Commit:** `feat(intercept,cli): MLP2-026 UnblockCascade IPC + CLI subcommand + clear telemetry`
