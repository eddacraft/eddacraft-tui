## Known Issues

### ink-testing-library Interactive Test Limitation

The ink-testing-library cannot properly test keyboard-driven state transitions:

- `stdin.write()` triggers `useInput` handlers synchronously
- React state updates are batched and async
- State doesn't propagate between sequential `stdin.write()` calls

**Impact:** Interactive navigation tests (arrow keys, vim bindings) must be
tested manually or via PTY-based E2E framework.

**Documented in:**
`cli/src/tui/commands/new/__tests__/template-browser.test.tsx`

### Pre-existing Flaky Test (Unrelated)

`core/src/architecture/baseline.test.ts:246` - Timing race where `updated_at`
equals `created_at` when test runs faster than timestamp resolution.
