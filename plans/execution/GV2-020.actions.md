# GV2-020 — Multi-graph registry and typed query traits — execution steps

**Branch:** `feat/gv2-020` · **Started:** 2026-06-15 · **Module:**
[graph-v2-foundation](../archive/modules/graph-v2-foundation.aps.md)

## Goal (from APS)

One typed in-process entry point for querying joined graph state without coupling
consumers to storage or `petgraph` internals. Registry exposes graph handles +
join queries for semantic, dependency, trust, control, and provenance graphs;
consumers depend on **traits**, not concrete storage.

## Design ground truth (Explore map, 2026-06-15)

| Graph | Reality | Registry treatment |
| ----- | ------- | ------------------ |
| semantic (`SymbolGraph`) | real, in-crate | real handle + queries |
| dependency (`DependencyGraph`) | real, in-crate | real handle + queries |
| trust (`TrustGraph`) | real, in-crate | real handle + join query |
| control/session (GV2-013) | **contract-only** (SessionRecord/Attribution in INTD proto; no in-crate graph) | **trait stub** `ControlJoin` + `WorkspaceRoot` relativiser bridge |
| plan/provenance (GV2-014) | **contract-only** (ref-only anchors: APS id, SHA, `SymbolIdentity`, `MemoryId`; bodies stay in TS Edda) | **trait stub** `ProvenanceJoin` (signature only) |

**Scope decision (ADR-064-aligned):** GV2-020 ships real handles+joins for
semantic/dependency/trust and **trait-stub** query surfaces for control/
provenance. It does **not** add cross-crate deps (INTD/Edda) into
`anvil-graph-cache`; the live control/provenance impls are brought by consumers
(GV2-023/GCTX). This matches "code [contract surface] lands with GV2-020" for the
013/014 named-not-frozen contracts.

**Seal invariant:** the hot-read surface (`HotReadApi`) is sealed via the private
`sealed::Sealed` supertrait + `HotPathSurface` marker; denylist ops live on
`BackgroundReadApi` (`impact_closure_unbounded`). The registry must preserve the
seal — the hot accessor returns `HotReadApi`, never widens it.

## TDD steps

1. **Registry skeleton + handle accessors** (`src/registry.rs`, export from
   `lib.rs`). `GraphRegistry<'a>` borrows `&SymbolGraph`, `&DependencyGraph`,
   `&TrustGraph`. Accessors: `semantic()`, `dependency()`, `trust()`,
   `hot_read() -> HotReadApi`, `background_read() -> BackgroundReadApi`.
   - RED→GREEN test: `registry_exposes_each_graph_handle` — construct over a small
     fixture, assert handle reads (`node_count`, `file_count`, `trust.len`).
2. **Cross-graph join query** `dependents_with_trust(file) -> Vec<(String,
   TrustLevel)>` joining dependency (importers) × semantic (their symbols) × trust
   (max posture). Plus `symbol_trust(&SymbolIdentity)`.
   - test: `registry_join_query_code_trust` — importer file + its max trust level.
3. **Provenance anchor join (ref-only)** `provenance_anchors(&SymbolIdentity) ->
   Vec<ProvenanceAnchor>` via the `ProvenanceJoin` trait stub (returns anchors
   supplied by an injected resolver; default resolver = empty). Satisfies the
   "code/trust/provenance" join-query validation without a Rust provenance graph.
   - test: `registry_join_query_spans_provenance_anchor` with a stub resolver.
4. **`WorkspaceRoot` relativiser bridge** in `anvil-kernel-types` (control/session
   join key: worktree-root → workspace-relative file). `ControlJoin` trait stub in
   the registry consumes it.
   - test: `workspace_root_relativises_under_root` + `…_rejects_outside_root`.
5. **Negative test — seal preserved through the registry.** `compile_fail`
   doctest: a denylist op (`impact_closure_unbounded`) is NOT reachable from
   `registry.hot_read()`; it IS reachable from `registry.background_read()`.
6. **E2E — `validate_paths` through the registry path.** Add a `with_registry`
   accessor on `KernelGraphCache` (`anvil-intercept`) that yields a
   `GraphRegistry`; route a certify through `registry.hot_read().certify(...)` and
   assert a **non-vacuous** verdict (real importer chain, no zero-callers) equal to
   the direct path. Reuses the `backing_parity` fixture pattern in
   `kernel_cache.rs`.

## Validation

`cargo test -p eddacraft-anvil-graph-cache -- registry` (steps 1-5) +
`cargo test -p eddacraft-anvil-intercept -- registry` (step 6).
Workspace gates before push: `cargo clippy --workspace --all-targets -- -D
warnings`, `cargo fmt --all --check`.
